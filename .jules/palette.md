## 2025-04-24 - Interactive Dropzone Accessibility Pattern
**Learning:** Next.js apps often implement file dropzones as stylised `<div>` elements wrapped around hidden `<input type="file">` elements. This inherently breaks keyboard navigation (tabbing) and screen reader identification (role) if not explicitly addressed. Simply placing an inner `<button>` triggers "nested interactive element" errors because the outer div is also intended to be clickable. Focus utility classes (`focus-visible:ring-*`) are also often missed on custom interactives compared to standard buttons.
**Action:** When converting non-interactive wrappers to clickable dropzones, apply `role="button"`, `tabIndex={0}`, an explicit `aria-label`, standard `focus-visible` ring utilities, and an `onKeyDown` handler matching 'Enter' and 'Space'. Replace any inner `<button>` elements with `<span>` styled with `group-hover` utilities (adding `.group` to the parent) to maintain visual interactivity without violating HTML semantics.
