## 2024-05-22 - Semantic Headings as Labels
**Learning:** When visual design uses section headings (h2) as the primary label for an input, use `aria-labelledby` to associate them programmatically without duplicating text in a hidden label.
**Action:** In future forms with section-based layouts, check if the section header serves as the label and link it via ID instead of adding redundant `sr-only` labels.

## 2025-02-18 - Syncing Visual and ARIA Labels
**Learning:** When using a helper function to generate a dynamic visual label (e.g., "High", "Medium", "Low" for a range input), reuse that same helper for the `aria-valuetext` attribute to ensure the screen reader experience perfectly matches the visual experience and stays in sync during maintenance.
**Action:** Extract label logic into a helper function and use it for both the visual element and the `aria-valuetext` prop.

## 2025-04-28 - Dropzone Keyboard Accessibility and Invalid Nesting
**Learning:** Custom interactive elements like file dropzones (`<div onClick={...}>`) often lack native keyboard accessibility and proper focus states. Simply adding `onClick` is insufficient; they require `role="button"`, `tabIndex={0}`, and `onKeyDown` handlers for "Enter" and "Space" to mimic native buttons. Furthermore, placing a visual `<button>` *inside* an interactive `<div role="button">` creates invalid, nested interactive HTML. To maintain design while fixing accessibility, convert the inner `<button>` to a `<span>` and synchronize hover effects using the `group-hover` Tailwind utility class on the inner element, paired with the `group` class on the parent.
**Action:** When auditing or implementing custom clickable areas (like dropzones or complex cards), always ensure the "Holy Trinity" of custom buttons (`role`, `tabIndex`, `onKeyDown`) is present, apply `focus-visible` utility classes for clear keyboard focus states, and never nest `<button>` elements within them. Use `<span>` and `group-hover` for internal visual buttons instead.
