## 2026-05-06 - Avoid Information Leakage in API Routes
**Vulnerability:** The API routes (`app/api/vision/route.ts`, `app/api/batch/route.ts`, `app/api/mutate/route.ts`, and `app/api/generate/route.ts`) were extracting the `error.message` from thrown exceptions and passing it as the `details` parameter to the `createErrorResponse` helper. This exposed internal error details and stack traces to clients, potentially revealing sensitive information about the backend.
**Learning:** In a Next.js App Router context, standard error-handling catch blocks must be careful not to forward internal error messages directly to the client response, especially when using generic, centralized error-response generators like `createErrorResponse`.
**Prevention:** Always sanitize error messages in API routes before sending them to the client. When using the `createErrorResponse` helper in this codebase, explicitly pass `undefined` as the `details` parameter in `catch` blocks to prevent information leakage, while continuing to use `console.error` for server-side logging of the full error details.
