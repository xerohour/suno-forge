## 2025-04-05 - Fix Insecure Input Clamping in Batch API
**Vulnerability:** The `/api/batch` endpoint attempted to 'fix' invalid `count` parameters by silently clamping them to valid bounds (1-50) before validation. This is a security anti-pattern as it bypasses strict input validation and potentially enables DoS regressions if large payloads are accepted silently.
**Learning:** Normalizing or 'fixing' user input before validation masks malicious or malformed requests and violates the fail-fast principle. Always validate raw input strictly and reject out-of-bounds requests with a 400 Bad Request error.
**Prevention:** Remove pre-validation modification of input (e.g., clamping). Implement strict validation of the raw input type and bounds (e.g., `typeof rawCount !== 'number' || rawCount < 1 || rawCount > 50`) and return a 400 error. Maintain backward compatibility by preserving default fallback logic for optional parameters (e.g., defaulting `count` to 1 if missing) only after verifying the raw input wasn't maliciously provided out-of-bounds.
