## 2024-05-24 - DoS Prevention via Input Length Validation
**Vulnerability:** API endpoints and validation layers (e.g. `/api/mutate`, `/api/vision`, and `validatePromptConfig`) were performing expensive string operations like `.trim()` or accepting massive arrays and strings without first checking length constraints. This allows a malicious user to send a multi-megabyte string and cause a Denial of Service (DoS) by maxing out CPU and memory allocations when parsing or trimming the inputs.
**Learning:** Due to how V8 and Node handle massive string allocations, calling methods like `.trim()`, replacing text, or mapping massive arrays on arbitrary user input can block the main thread. It's necessary to validate lengths *before* operating on the text.
**Prevention:** I established standard size boundaries in `lib/validation.ts` (`MAX_TITLE_LENGTH`, `MAX_SHORT_TEXT_LENGTH`, `MAX_LONG_TEXT_LENGTH`, `MAX_TAGS_COUNT`) and explicitly checked input length *before* calling `.trim()` or pushing them through engines. All future input string processing should first validate length limits to protect the server from resource exhaustion.
