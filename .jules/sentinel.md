## 2025-02-14 - Fix Input Clamping Bypass in Batch API
**Vulnerability:** The batch generation API (`app/api/batch/route.ts`) was using input clamping (modifying the input value) before validation instead of failing fast. An attacker could send a request with a massive `count` (e.g., 1000) or negative count (e.g., -5) and instead of rejecting it, the server would clamp it and silently process the request. While clamping constrained the load on the server, it meant the system accepted and processed malformed, potentially malicious requests, obscuring bad behavior and making rate-limiting or abuse detection harder. This violates fail-safe design principles.
**Learning:** Normalizing or "fixing" input (e.g., clamping) before validation is a security anti-pattern. Validation should be strict and reject invalid input immediately with a 400 Bad Request error. The `validateBatchRequest` already handled the proper bounds checking, but it was bypassed by the clamping logic modifying the `rawCount` payload beforehand.
**Prevention:** Always validate the raw request body first. Ensure out-of-bounds or malicious requests are rejected with a 400 error. Only apply default fallbacks (e.g., defaulting `count` to 1) for optional, unprovided parameters, never for actively malformed parameters.
