
## 2025-04-20 - Insecure Input Clamping Masking Validation in Batch API
**Vulnerability:** A DoS risk existed in `app/api/batch/route.ts` where an excessively large `count` value (e.g., 1000) was pre-processed by clamping to `Math.max(1, Math.min(50, rawCount))` *before* passing the input to the validation function. This allowed potentially malicious or overly large payloads to be silently accepted and processed (generating 50 prompts) instead of explicitly failing. Additionally, the error handler leaked stack trace information.
**Learning:** Pre-validation modification (like clamping or sanitizing) can mask invalid input and bypass the intent of fail-fast strict validation, violating the principle of failing securely on unexpected input and potentially leading to resource exhaustion or unexpected behavior.
**Prevention:** Always perform strict validation on raw input (including type and bounds checks, and `Number.isNaN` for numbers) *before* or *instead of* automatic modification/clamping. If an input is invalid or out of bounds, fail fast with a 400 Bad Request rather than attempting to "fix" it silently. Maintain fallback defaults only for missing/optional data.
