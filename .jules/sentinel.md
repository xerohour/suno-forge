## 2024-05-24 - DoS Vulnerability via Input Clamping Anti-pattern
**Vulnerability:** The batch generation API endpoint (/api/batch) was previously clamping out-of-bounds `count` values (e.g., negative numbers or extremely large numbers) to be within the 1-50 range instead of rejecting the request.
**Learning:** Normalizing or "fixing" input (like clamping) before validation is a security anti-pattern. While the original clamping effectively restricted the load on the backend, it creates a subtle vulnerability where malicious requests with excessively large payloads are technically processed rather than fail-fast, leading to potential regressions if that normalization logic is changed. Furthermore, it masks underlying issues with clients sending bad data.
**Prevention:** Always validate raw request bodies directly. If data is out of bounds, fail fast and return a 400 Bad Request error. Only apply default fallbacks for missing (undefined) optional parameters, never to "fix" invalid ones.
